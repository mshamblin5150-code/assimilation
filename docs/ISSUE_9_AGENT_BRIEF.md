### Desired behavior and key interfaces

The interface is `--git-executable ABSOLUTE_PATH`, which itself opts
into the version check. No argument means the existing passive behavior. Help
describes selection, trust assumptions, output limits and refusal behavior.

For the Windows scope, accept only a nonempty fully qualified drive-rooted path
to an `.exe`; spaces and Unicode are supported. Refuse relative/drive-relative
paths, UNC/device/extended namespaces, alternate data stream syntax, traversal
components, wildcard/NUL/control characters, trailing-dot/space aliases, and
shell scripts/wrappers before launch. Parse lexically; do not search PATH, expand
environment variables, resolve links, enumerate drives/directories, or inspect
unexpected payloads. Unknown CLI arguments or duplicate selections refuse.
An explicit check on a non-Windows runtime returns a bounded unsupported-platform
diagnostic; preserve the existing passive cross-platform report.

The operator is responsible for selecting an existing trusted local installation
whose executable, dependencies and path components are stable and trustworthy.
A drive-rooted spelling is not proof of a local volume, absence of reparse points
or authenticated object identity. Establishing those properties is outside this
trust-based diagnostic. Do not advertise these lexical checks as confinement.

Invoke exactly the selected executable with the fixed `--version` argument,
without a shell, interactive input, fallback executable or retry. Use no source
operation, transport test, repository/config inspection or automatic repair.
Do not reuse a runner that performs PATH lookup or source-operation setup.
Keep the existing environment/config/helper suppression policy where applicable,
and document required Windows startup variables without printing their values.
This is a trusted-process invocation, not a sandbox or a universal no-I/O claim
about arbitrary executables or their dependencies.

Confirmed resource defaults: a five-second child execution deadline after process
creation, and at most 4 KiB combined captured stdout/stderr before refusal.
Enforce the output cap while consuming bytes, rather than truncating after an
unbounded capture. On timeout or overflow, stop and reap the direct child and
close owned pipes/readers; test cleanup. Process creation and OS termination
latency are not covered by a claimed hard wall-clock bound. Do not claim hostile
descendant-process containment; report any cleanup failure without retrying.

Accept exit zero with one bounded ASCII version record of the form
`git version X.Y[.Z...][vendor suffix]`, where X and Y are decimal digits and
the remaining version token contains only ASCII letters, digits, dots, pluses,
underscores and hyphens. Permit one LF/CRLF terminator and require empty stderr.
Return only the parsed version token, not raw child output. Empty/multiple-line,
malformed, control-bearing, non-ASCII or oversized output refuses. A nonzero
child exit refuses even if stdout resembles a version.

Return structured report JSON on success and failure:

- Passive mode preserves its existing report and exit behavior.
- Explicit success: exit 0, top-level observed-not-qualified, Git availability
  available, discovery not-probed, execution observed, version parsed,
  compatibility unverified.
- Requested-check failure: exit 1, top-level blocked, Git availability/version
  unverified, compatibility unverified and a bounded reason code. Distinguish
  launch-failed, timeout, output-limit, invalid-output, nonzero-exit and
  cleanup-failed without raw exceptions, paths, environment values or stderr.
- Invalid selection/arguments or unsupported explicit-check runtime: exit 2,
  structured blocked diagnostic, no launch. Preserve the other safely observable
  prerequisite fields when available; an observation failure remains bounded.
- All modes retain installation_admitted, filesystem_verified and
  source_verified as false. No success implies permission to use an installer.
