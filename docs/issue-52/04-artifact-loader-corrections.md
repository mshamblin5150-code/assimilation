## Loader findings that change the correction requirements

All SpeechBrain findings below refer to commit c0241278f93ef02cd5191f03caf4e5f8e1292bf6.

1. **Download-only still constructs YAML objects.** In [pretrained_from_hparams](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/inference/interfaces.py#L123), fetch is followed by load_hyperpyyaml and pretrainer collection; only then is download_only tested to skip checkpoint loading and interface construction. It is not a passive acquisition route. The YAML contains !new constructors. The source itself warns that this interface can download/run arbitrary code.

2. **The supported revision control propagates, but defaults are mutable.** The same FetchConfig is passed to the top-level configuration fetch and Pretrainer.collect_files, which passes it to each artifact fetch. FetchConfig.revision reaches Hugging Face Hub. This narrows the original mutable-nested-source finding: the default unpinned path is a problem, but this version has an explicit shared revision mechanism. Do not assume a bare undocumented revision keyword on from_hparams performs the pin. [Interface](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/inference/interfaces.py#L183), [collection](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/utils/parameter_transfer.py#L245), [fetch configuration](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/utils/fetching.py#L219).

3. **A pin does not validate an existing destination.** fetch returns an existing destination before remote revision resolution unless overwrite/updates require otherwise. That return path performs no content-hash comparison. Neither allow_network=False nor a changed revision proves cached bytes match. Future acquisition must use a distinct reviewed staging destination and verify every actual file before parsing/loading. Future execution must resolve reviewed local paths and enforce host-level no-egress independently. These are design requirements, not instructions to run a fetch now. [Pinned fetch implementation](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/utils/fetching.py#L340).

4. **The default load set is larger than the pairwise scoring path.** The YAML declares embedding_model, mean_var_norm_emb, classifier and label_encoder as loadables. Pretrainer collects/loads all enabled entries. The [pairwise scorer](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/inference/speaker.py) uses encode_batch(normalize=False), then cosine similarity and strict score > threshold. [Encoder source](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/inference/classifiers.py#L71) shows classifier labels are not used on that path. This suggests a smaller reviewed configuration, but removing loadables changes the candidate: preserve the original, hash the derived configuration and test equivalence before claiming a reduced set is sufficient. No reduction was implemented here.

5. **Checkpoint loading is type-dispatched and version-sensitive.** Pretrainer prefers a custom hook, then a registered transfer hook, then a registered load hook. Module transfer reaches [torch_patched_state_dict_load](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/utils/checkpoints.py#L182); normalization has its [own torch.load hook](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/processing/features.py#L1536); the [categorical encoder](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/dataio/encoder.py#L791) parses Python literals. The inspected torch.load calls omit an explicit weights_only argument. PyTorch 2.7 documents a restricted default; therefore omission alone does not prove unrestricted pickle execution. Freeze the actual Torch version and relevant environment before assessing behavior. In PyTorch 2.7, TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1 changes implicit callsites to unrestricted loading, while TORCH_FORCE_WEIGHTS_ONLY_LOAD=1 forces restricted loading. Record their absence/presence rather than assuming the documented default; this observation is not permission to change the environment; never silently switch to weights_only=False or add globals merely to make a checkpoint load. [PyTorch load contract](https://docs.pytorch.org/docs/2.7/generated/torch.load.html), [serialization limits](https://docs.pytorch.org/docs/2.7/notes/serialization.html#torch-load-with-weights-only-true). Restricted loading still does not establish model safety or authenticity.

6. **Successful construction is not complete parameter compatibility evidence.** The [default module transfer hook](https://github.com/speechbrain/speechbrain/blob/c0241278f93ef02cd5191f03caf4e5f8e1292bf6/speechbrain/utils/checkpoints.py#L235) calls load_state_dict with strict=False and logs missing/unexpected keys. This does not prove these checkpoints are incompatible. Future reviewed runs must retain those diagnostics and stop on unexplained key mismatches; object construction alone is not a verified complete load.

## Trial and lifecycle contract: fixed structure, unresolved artifact binding

The following is a proposed research contract, not a fully frozen benchmark or execution permission. Generator/voice mapping and every generated-byte hash must be filled and independently reviewed before freezing it.

- Reserve artificial condition IDs S01–S12; calibration S01–S04, held-out S05–S12. For each, reserve two enrollment utterances E01/E02 and four probes P01–P04. Exact text, synthesis parameters, source data closure, rate/channel conversion and output hashes must be fixed without looking at held-out scores.
- Use a normalized centroid of the two enrollment embeddings; record this adaptation separately from upstream file-pair verification. Calibration: 16 matching and 48 ordered nonmatching comparisons. Held-out: 32 matching and 224 ordered nonmatching comparisons. These are correlated artificial comparisons, not independent human-speaker trials.
- Freeze threshold selection before evaluation: candidate grid -1.00 through 1.00 in 0.01 increments; minimize calibration mean of false-match and false-nonmatch fractions, ties choosing the higher threshold. Use strict score > threshold. This is a declared equal-cost research choice, not a production acceptance criterion.
- Do not select or freeze a threshold if a required enrollment embedding or centroid is zero/nonfinite, or a required calibration score is missing/nonfinite. Preserve failed trial records and investigate the failure before calibration; do not tune on a successful subset.
- Keep attack strata separate: exact replay; another artificial configuration; newly generated speech for the same artificial configuration; missing/wrong challenge; noise/channel corruption; empty/malformed input; loader timeout/error. Freeze source/target pairs, text and transforms for each stratum. No voice-cloning-resistance claim follows from this generator. Attempt counts and generation mapping remain unresolved; do not invent denominators.
- Never drop failures from a success denominator. Report score/decision coverage, failure types and stratum counts separately. Acoustic match acceptance cannot authorize an action. Authentication/permission behavior remains in the separately held simulator plan; no live trusted-auth mechanism is introduced here.

Before any generation or acquisition, the authorized host record must name: exact OS/runtime; nonprivileged identity; immutable inputs; isolated workspace; independently enforced egress policy; absence of mounted personal data/credentials; and inventories for outputs, Hugging Face/SpeechBrain caches, temp directories, crash/core logs, snapshots and backups. Local-only processing is preserved. Proposed synthetic expiry is at most seven days from generation, with temporary files removed at run end; this remains a review proposal. Record actual expiry, cleanup method, inspected paths and residual-copy limitations before claiming deletion. No Drive folder/upload or host isolation control was created or tested.
